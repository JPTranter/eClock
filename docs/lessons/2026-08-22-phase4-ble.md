  The crash is later.

## LED colour key (current test firmware uses BLUE for each step)

**CRITICAL: XIAO nRF52840 RGB LED is COMMON ANODE — active LOW.**
`LOW = ON`, `HIGH = OFF`. The opposite of typical Arduino. `initVariant()`
sets all three HIGH (all off) at boot. Writing LOW lights the LED.

Code has stepped prints `[A] sd_softdevice_enable` → `[B] sd_ble_cfg_set` → `[C] sd_ble_enable`
→ `[D] name` → `[E] adv config` → `[F] adv start`. **Last line printed = crash point.**
Success = `[OK] BLE advertising as 'ePaper Clock'` + solid GREEN.

## Key S140 v7.3 API gotchas (from headers in `framework-arduinoadafruitnrf52-seeed`)

- `sd_ble_gap_adv_start(uint8_t adv_handle, uint8_t conn_cfg_tag)` — **not** a params struct.
- `sd_ble_gap_adv_set_configure(&adv_handle, &ble_gap_adv_data_t, &params)` is the new way.
- `MSEC_TO_UNITS`/`UNIT_0_625_MS` macros **missing** from include path in this core;
  use raw `480` for 300ms.
